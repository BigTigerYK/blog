# Astro 博客文章写作风格与规范指南 (Style Guide)

本指南旨在规范博客文章的结构、排版、组件使用及语气调性，确保所有产出内容（包括 AI 辅助生成内容）具备高度的一致性和可读性。

## 1. Frontmatter 元数据规范

每篇文章的顶部必须包含完整且格式正确的 Frontmatter。请严格遵守以下字段与类型限制：

```yaml
---
title: "文章标题（控制在 30 字以内，直击主题）"
date: 2026-06-25 # 统一使用 YYYY-MM-DD 格式
categories: "分类名称" # 必须是双引号字符串，如 "无代码" 或 "前端开发"
tags: ["标签1", "标签2"] # 必须是数组格式，全小写或首字母大写，不带空格
id: "unique-post-id" # 唯一且扁平的字符串 ID，建议使用英文连字符
cover: "banner/filename.webp" # 封面图路径，必须存放在 banner/ 目录下，且格式为 webp
---
```

## 2. 语气调性与排版基础

### 语气与调性

* **口语化与亲和力**：采用大白话的技术教程风格，像在和朋友分享经验，拒绝晦涩、说教式的学术文风。
* **直奔主题**：开篇用 1-2 句话点明文章解决什么问题或带来什么价值，不写冗长的铺垫。

### 段落与排版

* **短小精悍**：单段字数控制在 **2-3 句话**以内，多用换行来制造视觉呼吸感，极其适合屏幕阅读。
* **中英混排空格**：中文与英文单词、数字之间**必须加空格**。例如：`使用 Astro + TypeScript 架构`（而不是`使用Astro+TypeScript架构`）。
* **重点加粗**：对核心步骤、关键配置项、重要结论进行 **加粗强调**，引导读者视线。

## 3. 文章结构与标题规范

文章整体采用**总-分-总**或**问题-解决-总结**的逻辑架构。

* **标题层级**：禁止在正文中使用 `#`（由 Astro 自动生成文章大标题）。
* `##` 用于大章节（如：系统配置、核心功能、常见坑点）。
* `###` 用于大章节下的具体步骤或细分项。
* 尽量避免使用 `####` 及更深层级，若内容过细，请改用列表。

## 4. Markdown 扩展与组件使用规范

为了保持页面丰富度，必须积极且合理地使用主题支持的扩展组件。

### 4.1 提示框组件 (`:::note`)

不能滥用，仅在需要强调、警告或提供额外背景时使用。

| 类型 (`type`) | 使用场景 | 示例 |
| --- | --- | --- |
| `info` | 延伸知识、补充说明、小贴士 | `:::note{type="info"}\n内容\n:::` |
| `success` | 阶段性成果、验证成功的状态 | `:::note{type="success"}\n内容\n:::` |
| `warning` | 避坑指南、版本兼容问题、高风险操作 | `:::note{type="warning"}\n内容\n:::` |

### 4.2 按钮组件 (`::btn`)

用于引导用户跳转到外部资源。通常出现在文章开头（如源码地址）或文章结尾（如延伸阅读）。

* **规范**：`::btn[按钮文字]{link="https://example.com"}`

### 4.3 表格、代码块与列表

* **代码块**：必须显式声明语言类型（如 `bash`, `typescript`, `json`），长代码必须写注释。
* **列表**：步骤类内容一律使用数字列表（`1. 2. 3.`），并列特性一律使用无序列表（`*`）。
* **表格**：多维度的参数对比、配置项说明，一律转换为 Markdown 表格呈现。

## 5. 分类与标签 (Taxonomy) 规范

为了保证聚合页面的整洁，分类与标签需要收敛，禁止野蛮生长：

* **`categories` (分类)**：属于大方向划分，采用**单数**形式的字符串。目前围绕项目聚焦在 `"无代码"`、`"前端技术"`、`"效率工具"` 等。
* **`tags` (标签)**：属于技术栈或具体工具名，采用**数组**形式。例如：`["nocodeflow", "astro", "cloudflare-pages"]`。统一使用小写。
